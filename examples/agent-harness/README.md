# Agent Harness на tvision-rs

Самостоятельное терминальное приложение на Rust: чаты, настройки Qwen/OpenAI-compatible API, цикл вызова инструментов, подтверждения, журнал SQLite и продолжение прерванных задач. Интерфейс использует библиотеку tvision-rs из корня репозитория. Исполнитель — Python, его исходник встроен в EXE при сборке.

## Запуск в Windows

Нужны Rust stable и Python 3.10+ в PATH. Сначала из корня репозитория выполните `cargo +stable build --release --manifest-path examples/agent-harness/Cargo.toml`, затем перейдите в `examples/agent-harness` и запускайте `target/release/agent-harness.exe`. Ниже `agent-harness.exe` означает этот собранный файл. Запускайте EXE из PowerShell в каталоге, где должны храниться настройки и история:

```powershell
$env:DASHSCOPE_API_KEY = 'ваш актуальный ключ'
.\agent-harness.exe
```

F4 — задайте Base URL и модель из кабинета вашего провайдера. Base URL заканчивается на `/v1`, приложение добавляет `/chat/completions`. В адресе `https://WORKSPACE_ID.ap-southeast-1.maas.aliyuncs.com/compatible-mode/v1` замените `WORKSPACE_ID` действительным идентификатором. Адрес должен соответствовать ключу и региону. Поле ключа содержит **имя переменной окружения**, по умолчанию `DASHSCOPE_API_KEY`.

Модель должна поддерживать OpenAI-compatible function calling. Для понимания снимков нужна также поддержка изображений. Выберите такую модель в настройках; наличие этих возможностей зависит от провайдера. Ключ передаётся исполнителю через stdin и не записывается в настройки.

F6 — выберите существующую рабочую папку. Напишите, например: «Покажи файлы проекта, прочитай README и предложи изменения». F2 отправляет задачу. Ctrl+N создаёт чат, F8 останавливает исполнителя, F7 показывает последние запуски и результаты инструментов, F5 продолжает прерванный запрос. Alt+X выходит.

История и настройки сохраняются в `agent-chats.json`, журнал — в `agent-chats.runs.sqlite`. Можно передать другой путь первым аргументом EXE. Одна рабочая папка используется всеми чатами. Запускайте один экземпляр приложения на файл истории.

Ответы модели отображаются в `MarkdownViewer`: заголовки, списки, выделение и блоки кода. Запросы пользователя и события инструментов показываются буквальным текстом. Перенос строк обновляется при изменении размера окна; область истории прокручивается стрелками, PgUp/PgDn и Home/End, когда находится в фокусе.

## Инструменты

- Файлы: список, чтение с номерами строк и SHA256, поиск текста, атомарная запись. Файловый API ограничен рабочей папкой, проверяет реальный путь и SHA256 перед заменой. Создание файла требует существующего родительского каталога.
- Терминал: команда в рабочей папке, код возврата и вывод. Лимит 45 секунд и 2 МБ вывода. Вывод показывается после завершения команды.
- Интернет: загрузка публичной HTTP(S)-страницы, извлечение текста и ссылок; поиск через Brave Search API.
- Браузер: отдельный видимый Chromium, открытие URL, чтение страницы, нажатие и заполнение элементов, снимок. После действия нужно обновить наблюдение.
- Компьютер (Windows): список окон и UI Automation элементов, Invoke/Value действия, снимок экрана. Изменившееся дерево окна требует повторного наблюдения. Поля пароля не заполняются.

Для поиска установите `BRAVE_SEARCH_API_KEY` в окружении перед запуском. Для браузера установите Playwright в отдельный Python:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install playwright
.\.venv\Scripts\python.exe -m playwright install chromium
$env:HARNESS_PYTHON = (Resolve-Path .\.venv\Scripts\python.exe).Path
.\agent-harness.exe
```

Без Playwright остальные инструменты работают. По умолчанию браузер использует собственный временный профиль. Существующие пользовательские сессии не подключаются. Автоматизация рабочего стола реализована только для Windows через PowerShell и UI Automation; произвольные координатные клики и управление клавиатурой пока не реализованы.

## Подтверждения и восстановление

Чтение и поиск файлов не требуют диалога. Запись, терминал, интернет, браузер и компьютер каждый раз требуют явного подтверждения с аргументами. Команда терминала выполняется с полными правами пользователя: рабочая папка задаёт cwd, но не является песочницей. Подтверждённые чтения, страницы и снимки передаются модели; журнал хранится локально без шифрования.

Намерение инструмента сохраняется до исполнения. При F5 незавершённое действие не повторяется автоматически: модель получает сообщение о неизвестном результате и должна проверить состояние. F8 не отменяет уже произошедшие внешние изменения. Запись `running` в журнале означает, что окончание не подтверждено; после аварийного закрытия она может оставаться такой до продолжения.

Ограничения: 20 обращений к модели за запуск, проверка общего времени 10 минут между шагами, 90 секунд на API-запрос, остановка после трёх отказов пользователя. Подтверждения могут увеличить общее время. Это первая рабочая версия: ответ модели показывается целиком, токенового стриминга и автоматического сокращения контекста пока нет.

## Сборка и проверка

Команды выполняются из `examples/agent-harness`.

```powershell
cargo +stable build --release
python -m unittest discover -s tools -p test_harness.py
cargo +stable test --package agent-harness
cargo +stable clippy --no-deps -- -D warnings
```

Зависимость `tvision-rs` подключена из корня репозитория; Cargo не загружает внешние Rust-пакеты. Python-исполнитель использует стандартную библиотеку; Playwright нужен только браузеру. Тесты проверяют HTTP tool calling на локальном сервере, подтверждения, SQLite, восстановление, файловые ограничения, тайм-аут и Rust/Python протокол. Живой Qwen, браузер и действия UI Automation требуют отдельной интеграционной проверки.

Структура: `src/main.rs` — интерфейс и история, `src/api.rs` — запуск/остановка Python и протокол событий, `tools/harness.py` — реестр инструментов, API, разрешения и SQLite; `tools/test_harness.py` — проверки поведения. Для добавления инструмента расширьте `TOOLS` и `Runtime.execute`, сохранив проверку аргументов и подтверждение перед эффектами.
