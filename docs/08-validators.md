# 8. Проверка ввода

Строке ввода можно назначить **валидатор** (`TValidator`): он проверяет
текст по ходу набора и перед закрытием диалога.

```rust
use tvision::*;

fn fields(d: &mut Dialog) {
    // Дата: цифры и дефисы, дефисы дописываются сами.
    d.add(InputLine::new(Rect::new(3, 2, 15, 3), 10).with_validator(PictureValidator::new("##-##-####", true)));
    // Только шестнадцатеричные цифры.
    d.add(InputLine::new(Rect::new(3, 4, 15, 5), 8).with_validator(FilterValidator::new("0123456789ABCDEFabcdef")));
    // Целое от 1 до 100.
    d.add(InputLine::new(Rect::new(3, 6, 15, 7), 3).with_validator(RangeValidator::new(1, 100)));
    // Одно из значений списка.
    d.add(InputLine::new(Rect::new(3, 8, 15, 9), 10).with_validator(StringLookupValidator::new(&["да", "нет"])));
}
```

## Как работает проверка

* **По ходу набора** (`is_valid_input`): после каждого изменения строка
  ввода спрашивает валидатор; если ответ «нет», правка откатывается —
  неправильный символ просто не появляется. Валидатор может и дописать
  строку (автозаполнение литералов маски).
* **При закрытии** (`is_valid`): когда диалог закрывают командой, отличной
  от `cm::CANCEL`, строка ввода проверяет окончательное значение. При
  ошибке показывается окно с текстом `error_message()`, фокус
  возвращается в строку, диалог не закрывается.
* `status_ok()` — корректен ли сам валидатор (например, синтаксис маски).
  На проверку `valid(cm::VALID)` строка ввода отвечает этим значением,
  поэтому окно с неправильной маской `insert_window` не вставит.

## Готовые валидаторы

### `PictureValidator` — маска

`PictureValidator::new(маска, auto_fill)` — маска в стиле Paradox
(`TPXPictureValidator`):

| Символ | Значит |
|--------|--------|
| `#` | цифра |
| `?` | буква |
| `&` | буква, переводится в верхний регистр |
| `!` | любой символ, переводится в верхний регистр |
| `@` | любой символ |
| `;` | следующий символ маски — буквально (`;#` — знак «#») |
| `*` | повтор: `*3#` — три цифры, `*#` — сколько угодно цифр |
| `[ ]` | необязательная часть |
| `{ }` | группа |
| `,` | варианты: `{Да,Нет}` |
| остальное | литерал, вводится как есть |

Примеры:

| Маска | Что принимает |
|-------|---------------|
| `##-##-####` | дата `12-03-2024` (дефисы дописываются при `auto_fill`) |
| `(###) ###-####` | телефон |
| `#[#][#]` | число из 1–3 цифр |
| `&*?` | слово с заглавной первой буквой (`ivan` → `Ivan`) |
| `{Да,Нет}` | «Да» или «Нет»; с `auto_fill` «Д» дописывается до «Да» |
| `*#[.##]` | число с необязательными двумя знаками после точки |

При `auto_fill == true` литералы маски дописываются сами, как только
введённое однозначно к ним подводит.

Окончательное значение должно соответствовать маске **полностью**; пустая
строка маску не проходит. Если поле необязательное, используйте свой
валидатор (ниже).

Метод `picture(&mut s, auto_fill)` разбирает строку по маске и
возвращает `widgets::validate::PicResult`: `Complete`, `Incomplete`,
`Empty`, `Error`, `Syntax` и др. — пригодится для своих проверок.

### `FilterValidator` — допустимые символы

`FilterValidator::new("0123456789")` — в строке могут быть только эти
символы. Набор хранится в поле `valid_chars`.

### `RangeValidator` — целое в диапазоне

`RangeValidator::new(min, max)` — по ходу набора пропускает только цифры
и знаки (`-` только при `min < 0`), при закрытии проверяет, что число
лежит в `min..=max`. Данные строки ввода остаются строкой (`Value::Str`);
для числовых данных удобнее [`InputLong`](07-dialogs.md#числовое-поле-inputlong).

### `StringLookupValidator` — значение из списка

`StringLookupValidator::new(&["a", "b"])` — при закрытии значение должно
совпасть с одной из строк (поле `strings`). Набор по ходу ввода не
ограничивается; если нужен выбор только из списка с подсказкой —
используйте [`Combo`](07-dialogs.md#выпадающий-список-combo) с
`cbx::ONLY_LIST`.

### `FnValidator` — проверка функцией

```rust
use tvision::*;

fn email_field() -> InputLine {
    InputLine::new(Rect::new(3, 2, 40, 3), 60).with_validator(FnValidator {
        f: |s: &str| s.is_empty() || (s.contains('@') && s.contains('.')),
        message: "Введите адрес вида имя@домен.ru".into(),
    })
}
```

Проверяет только окончательное значение.

## Свой валидатор

Реализуйте трейт `Validator`. Обязателен только `error_message`;
`is_valid_input`, `is_valid` и `status_ok` по умолчанию всё разрешают.

```rust
use tvision::*;

/// Только латинские буквы и цифры, длина 3–16 (имя пользователя).
struct LoginValidator;

impl Validator for LoginValidator {
    fn is_valid_input(&self, s: &mut String, _suppress_fill: bool) -> bool {
        // Можно и исправлять ввод: приводим к нижнему регистру.
        *s = s.to_lowercase();
        s.chars().all(|c| c.is_ascii_alphanumeric()) && s.chars().count() <= 16
    }

    fn is_valid(&self, s: &str) -> bool {
        (3..=16).contains(&s.chars().count())
    }

    fn error_message(&self) -> String {
        "Имя: от 3 до 16 латинских букв и цифр".into()
    }
}

fn login_field() -> InputLine {
    InputLine::new(Rect::new(3, 2, 22, 3), 16).with_validator(LoginValidator)
}
```

`suppress_fill` — просьба не дописывать строку (передаётся при удалении
символов, чтобы автозаполнение не мешало стирать).

## Сообщения об ошибках на русском

Тексты стандартных валидаторов («Ввод не соответствует шаблону:»,
«Недопустимый символ», «Значение вне диапазона…», «Такого значения нет в
списке допустимых») переводятся вызовом
`locale::set_language(Language::Ru)` — см. [главу 13](13-locale.md).
