# Урок 10. Тесты

Программу с интерфейсом тоже можно проверять обычными тестами
`cargo test` — без терминала, без человека и без мыши. В каждом примере
уроков в конце файла есть такие тесты; разберёмся, как они устроены.

## «Невидимый» терминал

Обычно программа создаётся так: `Program::with_terminal(…)` — и рисует в
настоящий терминал. Для тестов есть **невидимый терминал**
`HeadlessBackend`:

* нажатия клавиш и щелчки берутся из **очереди**, которую заполняет
  тест;
* экран хранится в памяти — его можно прочитать как текст.

```rust,ignore
use tvision::platform::HeadlessBackend;

let mut b = HeadlessBackend::new(80, 25);   // экран 80×25
b.push_key(kb::F2);                         // «нажать» F2
b.push_key(kb::ENTER);
b.push_click(10, 5);                        // «щёлкнуть» в столбце 10, строке 5
let mut app = Program::new(Box::new(b), Some(menu()), Some(status()));
```

`Program::new(терминал, меню, строка состояния)` — то же, что
`with_terminal`, но с любым терминалом.

## Запустить и проверить

```rust,ignore
let mut h = App { greetings: 0 };
app.pump(&mut h);                 // обработать всю очередь
assert_eq!(h.greetings, 1);       // проверить данные
assert!(app.screen_text().contains("Файл"));   // проверить экран
```

* `app.pump(&mut обработчик)` — обработать все события из очереди и
  вернуться (в отличие от `run`, который ждёт выхода);
* проверять можно **данные** (поля обработчика, окна) и **экран**:
  `app.screen_text()` — весь последний кадр текстом.

## Пример целиком

Тест из урока 5: ввести имя в диалог и проверить, что программа его
запомнила.

```rust,ignore
#[test]
fn remembers_name() {
    let mut b = HeadlessBackend::new(80, 25);
    b.push_key(kb::F2);                              // открыть диалог
    for c in "Аня".chars() {                         // набрать «Аня»
        b.push_key(KeyEvent::new(Key::Char(c), Mods::NONE));
    }
    b.push_key(kb::ENTER);                           // нажать OK
    let mut app = Program::new(Box::new(b), None, Some(status()));
    let mut h = App { name: String::new() };
    app.pump(&mut h);
    assert_eq!(h.name, "Аня");
}
```

Запуск: `cargo test --example learn_05_dialog`. Все тесты библиотеки и
примеров — `cargo test --all-targets`.

## Окна, которые никто не закрыл

После OK пример показывает окно «Привет, Аня!». В тесте его никто не
закроет — и тест должен был бы зависнуть. Чтобы этого не случилось,
невидимый терминал, когда очередь кончилась, сам «нажимает» Esc: забытые
окна закрываются.

Обычно это то, что нужно. Но если ваше окно ждёт чего-то долгого
(например, загрузки файла в отдельном потоке), Esc его отменит. Тогда
выключите это: `b.esc_budget = 0;` — и следите, чтобы в тесте не
оставалось незакрытых окон.

## Что ещё удобно

* **Команда без клавиш:** `app.put_event(Event::command_event(CM_HELLO));
  app.pump(&mut h);` — как будто выбрали пункт меню.
* **Диалог отдельно:** `let (cmd, d) = app.exec_dialog(my_dialog());` —
  с очередью клавиш для этого диалога; потом проверить `cmd` и данные
  `d.get_data()`.
* **Без программы вовсе:** функции вроде `to_value` / `from_value` или
  раскладку диалога можно проверять напрямую. Тест `dialog_inside_frame`
  из урока 4 проверяет, что ни один элемент не налез на рамку:

```rust,ignore
let d = layout_dialog();
let s = d.win.group.vs.size;
let inside = Rect::new(1, 1, s.x - 1, s.y - 1);
for c in &d.win.group.children {
    let b = c.vs().bounds();
    assert_eq!(inside.intersect(&b), b, "{:?} залезает на рамку", b);
}
```
