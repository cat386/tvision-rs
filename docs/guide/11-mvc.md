# Урок 11. MVC: данные в JSON и SQLite

В уроке 9 мы написали «Контакты» вручную: своё окно, обмен данными с
диалогом, чтение и запись файла. Это полезно, чтобы понять, как всё
устроено, — но для каждой новой программы (склад, библиотека книг,
список задач) пришлось бы писать то же самое заново.

В этом уроке та же программа получится из **описания полей**: какие
поля есть у записи и какого они вида. Таблицу, диалог правки, проверку
ввода и сохранение в файл JSON или в базу SQLite библиотека сделает
сама — модуль `tvision::mvc`.

Программа урока: `cargo run --example mvc_contacts`.

## Что такое MVC

**Model–View–Controller** (модель — представление — контроллер) — способ
разделить программу с интерфейсом на три части, чтобы они не мешали
друг другу:

| Часть | Что делает | В `tvision::mvc` |
|-------|-----------|------------------|
| **Модель** | хранит данные и знает правила: какие поля обязательны, куда сохранять | `Model` + хранилище (`JsonStorage`, `SqliteStorage`) |
| **Представление** | показывает данные; само их не меняет | `ModelWindow` — окно с таблицей |
| **Контроллер** | принимает команды пользователя и меняет модель | `CrudController` — «Добавить», «Изменить», «Удалить» |

```text
  пользователь ── Ins, Enter, Del ──▶ Контроллер ── add / update / remove ──▶ Модель ──▶ файл .json / база .db
                                                                                │
  экран ◀──────────── Представление (таблица) ◀── читает записи ───────────────┘
```

Главная выгода: части можно менять по отдельности. Чтобы хранить
данные в базе вместо файла, меняется только хранилище — окно и
контроллер об этом даже не узнают.

## Шаг 1. Опишите поля

Запись — это строка таблицы. Её поля описывает **схема** (`Schema`):
имя таблицы и список полей.

```rust,ignore
use tvision::mvc::*;
use tvision::*;

fn schema() -> Schema {
    Schema::new(
        "contacts",                                          // имя таблицы в базе SQLite
        vec![
            Field::text("name", "~И~мя").required().max_len(60).width(22),
            Field::text("phone", "~Т~елефон").max_len(30).width(18),
            Field::text("email", "~П~очта").max_len(60).width(22).check(is_email, "В адресе почты нет «@»."),
            Field::choice("group", "~Г~руппа", &["Семья", "Работа", "Друзья"]),
            Field::bool("favorite", "Из~б~ранный").width(3),
        ],
    )
}

fn is_email(s: &str) -> bool {
    s.contains('@')
}
```

У каждого поля два имени:

* **`"name"`** — для хранения: ключ в JSON, столбец в базе. Латиницей,
  без пробелов.
* **`"~И~мя"`** — для человека: подпись в диалоге и заголовок столбца.
  Буква между тильдами — горячая клавиша (Alt+И).

**Вид поля** решает всё остальное:

| Создать | В таблице | В диалоге | Хранится как |
|---------|-----------|-----------|--------------|
| `Field::text(…)` | текст | строка ввода | строка |
| `Field::int(…)` | число справа | строка ввода, в которую можно набрать только цифры | целое |
| `Field::real(…)` | число справа | строка ввода (запятая или точка) | дробное |
| `Field::bool(…)` | `✓` | флажок | `true` / `false` (в базе — 1 / 0) |
| `Field::choice(…, &[варианты])` | текст варианта | переключатели | строка |

И уточнения — их можно писать цепочкой:

| Метод | Что делает |
|-------|-----------|
| `.required()` | поле нельзя оставить пустым |
| `.max_len(n)` | не больше `n` символов |
| `.width(n)` | ширина столбца таблицы |
| `.check(функция, сообщение)` | своя проверка: функция получает текст и возвращает `true`, если всё хорошо. Для пустого необязательного поля не вызывается |

## Шаг 2. Откройте модель

```rust,ignore
let model = Model::open(schema(), open_storage("contacts.json")?)?.into_ref();
```

Разберём изнутри наружу:

* `open_storage(путь)` выбирает **хранилище** по расширению файла:
  `.json` — файл JSON, `.db`, `.sqlite`, `.sqlite3` — база SQLite.
* `Model::open(схема, хранилище)` создаёт модель и сразу читает все
  записи. Файла ещё нет — не страшно: записей просто ноль, файл появится
  при первом изменении.
* `.into_ref()` заворачивает модель в `Rc<RefCell<…>>` (тип `ModelRef`).
  Так ей могут пользоваться сразу двое: окно (чтобы рисовать) и
  контроллер (чтобы менять).

> **`Rc<RefCell<T>>` за одну минуту.** `Rc` — «общий владелец»: копия
> `model.clone()` не копирует данные, а даёт ещё одну ссылку на ту же
> модель. `RefCell` разрешает менять общие данные: `model.borrow()` —
> прочитать, `model.borrow_mut()` — изменить. Одновременно `borrow_mut`
> и что-то ещё нельзя — программа остановится с ошибкой, поэтому не
> держите `borrow` долго (например, на время диалога).

## Шаг 3. Окно и контроллер

```rust,ignore
struct App {
    crud: CrudController,
}

impl AppHandler for App {
    fn handle_event(&mut self, app: &mut Program, ev: &mut Event) {
        self.crud.handle(app, ev);           // Добавить, Изменить, Удалить
    }
    fn idle(&mut self, app: &mut Program) {
        self.crud.update_commands(app);      // нет записей — «Изменить» и «Удалить» серые
    }
}

fn main() -> std::io::Result<()> {
    let model = Model::open(schema(), open_storage("contacts.json").unwrap()).unwrap().into_ref();
    let mut app = Program::with_terminal(Some(menu()), Some(status()))?;
    let r = app.desktop().group.vs.extent();                  // весь рабочий стол
    let crud = CrudController::open(&mut app, r, "Контакты", model);
    app.run(&mut App { crud });
    Ok(())
}
```

`CrudController::open` делает две вещи: вставляет на рабочий стол окно
`ModelWindow` с таблицей и создаёт контроллер, который знает это окно.

Осталось связать клавиши с командами. Команды записей уже есть в
модуле: `CM_RECORD_ADD`, `CM_RECORD_EDIT`, `CM_RECORD_DELETE`.

```rust,ignore
fn status() -> Vec<StatusDef> {
    vec![StatusDef::all(vec![
        StatusItem::new("~Ins~ Добавить", kb::key(Key::Ins), CM_RECORD_ADD),
        StatusItem::new("~F4~ Изменить", kb::f(4), CM_RECORD_EDIT),
        StatusItem::new("~Del~ Удалить", kb::key(Key::Del), CM_RECORD_DELETE),
        StatusItem::new("~Alt-X~ Выход", kb::ALT_X, cm::QUIT),
    ])]
}
```

Enter и двойной щелчок по строке окно превращает в `CM_RECORD_EDIT`
само.

Всё. Запустите:

```text
cargo run --example mvc_contacts
```

Ins открывает диалог «Новый контакт», собранный по схеме: строки ввода
с подписями, переключатели группы, флажок «Избранный». Попробуйте
оставить имя пустым или ввести почту без `@` — OK не закроет диалог, а
покажет сообщение. Щелчок по заголовку столбца сортирует таблицу.

## Где лежат данные

**JSON.** Без аргументов пример открывает файл `tvision-mvc-contacts.json`
во временном каталоге системы (и заполняет его образцом). Свой файл —
`cargo run --example mvc_contacts -- мои.json`. Внутри — массив объектов:

```json
[
  {
    "id": 1,
    "name": "Анна Петрова",
    "phone": "+7 900 111-22-33",
    "email": "anna@example.ru",
    "group": "Семья",
    "favorite": true
  }
]
```

Файл переписывается **после каждого изменения** — команды «Сохранить»
нет, и при выходе ничего не теряется. `"id"` — номер записи, его ставит
хранилище. Файл можно править и в обычном редакторе: объекты без `"id"`
получат номер при чтении, а ключи, которых нет в схеме, сохранятся как
были.

**SQLite.** База — один файл, но внутри — настоящая база данных с
запросами на SQL. Поддержка SQLite включается **признаком** (feature)
`sqlite`, потому что ей нужна системная библиотека `libsqlite3`:

```text
cargo run --example mvc_contacts --features sqlite -- контакты.db
```

В своём проекте признак включается в `Cargo.toml`:

```toml
[dependencies]
tvision-rs = { git = "https://github.com/cat386/tvision-rs", features = ["sqlite"] }
```

> Где взять `libsqlite3`: в macOS она есть всегда; в Ubuntu и Debian —
> `sudo apt install libsqlite3-dev`; в Fedora — `sudo dnf install
> sqlite-devel`; в Windows 10 и новее используется встроенная
> `winsqlite3.dll`.

Таблица `contacts` создаётся сама: столбец `id INTEGER PRIMARY KEY` и
по столбцу на поле. Добавили поле в схему — при следующем запуске
появится и столбец. Каждое изменение — сразу запрос `INSERT`, `UPDATE`
или `DELETE`.

Код программы для JSON и для SQLite **один и тот же** — в этом и смысл
модели.

## Свои команды над моделью

Контроллер умеет три команды. Остальное вы пишете сами — работая с
моделью, а не с таблицей. Например, «Сортировать по имени»:

```rust,ignore
CM_SORT_NAME => {
    self.crud.model.borrow_mut().sort_by(0, true);   // поле 0, по возрастанию
}
```

Таблицу обновлять не нужно: у модели есть счётчик изменений
`revision()`, окно замечает, что он вырос, и обновляется само.

Что умеет модель:

| Метод | Что делает |
|-------|-----------|
| `len()`, `get(i)`, `records()` | сколько записей, запись номер `i`, все записи |
| `add(запись)` | проверить, сохранить, добавить; вернёт номер строки |
| `update(i, запись)` | заменить запись `i` |
| `remove(i)` | удалить запись `i` |
| `sort_by(поле, по_возрастанию)` | сортировать; порядок соблюдается и для новых записей |
| `reload()` | перечитать файл |

Запись (`Record`) — это `id` и значения полей по порядку схемы:

```rust,ignore
let r = Record::new(vec!["Дарья".into(), "+7 999".into(), "".into(), "Друзья".into(), true.into()]);
self.crud.model.borrow_mut().add(r)?;
```

Если запись не прошла проверку или файл не записался, `add` вернёт
ошибку с текстом для человека, и модель **ничего не изменит** — данные
в памяти и на диске всегда совпадают.

## Несколько окон

Можно открыть несколько файлов сразу — каждое окно со своим
контроллером. Контроллер берёт команду, только если **его** окно
активно, поэтому Del удалит запись именно в том окне, где курсор. В
примере F3 открывает ещё один файл (`App` хранит `Vec<CrudController>`).

## Попробуйте

1. Добавьте в схему поле `Field::int("year", "~Г~од рождения")` и
   запустите с тем же файлом. Что стало со старыми записями? (Год у них
   пустой.) А с базой `.db`?
2. Сделайте телефон обязательным и запретите буквы в нём через
   `.check(…)`.
3. Добавьте команду «Только избранные»: удалите (`remove`) все записи,
   у которых `favorite` — «нет». Подсказка: `r.get(4).as_bool()`.
   Удаляйте с конца, чтобы номера не сдвигались.
4. Напишите тест как в уроке 10: Ins, имя, Enter — и проверьте, что в
   файле JSON появилась строка с этим именем.

## Важно запомнить

* Модель — данные и правила, представление — показ, контроллер —
  команды. Меняется только модель.
* Поля описываются схемой; диалог, проверка и столбцы получаются из неё.
* `open_storage` выбирает JSON или SQLite по расширению файла;
  программа от этого не меняется.
* Изменения сохраняются сразу — «Сохранить» не нужно.
* SQLite включается признаком `sqlite` и требует `libsqlite3`.
