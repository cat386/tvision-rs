## `Point` — точка

**Что это.** Два числа: `x` (столбец) и `y` (строка). Счёт с нуля, `y`
растёт вниз. Тем же типом задают **размер**: `x` — ширина, `y` — высота.

**Аналог в Turbo Vision:** `TPoint`.

```rust
use tvision::*;

fn points() {
    let a = Point::new(10, 5); // столбец 10, строка 5
    let b = Point::new(2, 1);
    assert_eq!(a + b, Point::new(12, 6)); // сложение по координатам
    assert_eq!(a - b, Point::new(8, 4));
    let size = Point::new(40, 10); // как размер: ширина 40, высота 10
    assert_eq!(size.x * size.y, 400);
}
```

**Что важно знать.**

* Координаты — `i32` и могут быть отрицательными (окно, утащенное за
  левый край экрана).
* Поддерживаются `+`, `-`, `+=`, `-=`.

## `Rect` — прямоугольник

**Что это.** Прямоугольник на экране: левый верхний угол `a` и правый
нижний `b`. **Правый и нижний край в прямоугольник не входят**, поэтому
ширина — просто `b.x - a.x`.

**Когда нужен.** Почти везде: им задают положение и размер окна,
кнопки, поля — любого представления.

**Аналог:** `TRect`.

```rust
use tvision::*;

fn rects() {
    let r = Rect::new(2, 1, 12, 4); // столбцы 2..11, строки 1..3
    assert_eq!((r.width(), r.height()), (10, 3));
    assert!(r.contains(Point::new(11, 3)));
    assert!(!r.contains(Point::new(12, 3))); // правый край — уже снаружи

    let inner = r.grown(-1, -1); // сжать на клетку с каждой стороны
    assert_eq!(inner, Rect::new(3, 2, 11, 3));
    let moved = r.moved(5, 0); // сдвинуть на 5 вправо
    assert_eq!(moved, Rect::new(7, 1, 17, 4));
    assert_eq!(r.intersect(&moved), Rect::new(7, 1, 12, 4)); // общая часть
    assert_eq!(r.union(&moved), Rect::new(2, 1, 17, 4)); // охватывающий
}
```

**Как создать.**

* `Rect::new(x1, y1, x2, y2)` — по углам. Удобная запись:
  `Rect::new(x, y, x + ширина, y + высота)`.
* `Rect::from_origin_size(угол, размер)` — по углу и размеру.

**Главное.**

| Метод | Что делает |
|-------|-----------|
| `width()`, `height()`, `size()` | ширина, высота, размер (`Point`) |
| `contains(точка)` | попадает ли точка внутрь |
| `is_empty()` | пустой ли (ширина или высота ≤ 0) |
| `moved(dx, dy)` | сдвинутая копия |
| `grown(dx, dy)` | шире на `dx` и выше на `dy` **с каждой стороны**; отрицательные — уже |
| `intersect(&r)` | общая часть двух прямоугольников |
| `union(&r)` | наименьший прямоугольник, охватывающий оба |
| `a`, `b` | углы (их можно менять напрямую) |

`moved` и `grown` возвращают новый прямоугольник, исходный не меняется.

Как прямоугольники складываются в раскладку окон — [урок 4](04-coordinates.md)
и [координаты подробно](22-views.md#координаты-подробно).

## `Attr` — цвет

**Что это.** Цвет одной клетки: цвет символа и цвет фона в одном числе
(`u32`). Младший байт устроен как в DOS: младшие 4 бита — цвет текста,
старшие 4 — фон. `0x1E` — жёлтый (`E`) на синем (`1`).

16 основных цветов:

| № | Цвет | № | Цвет |
|---|------|---|------|
| 0 | чёрный | 8 | тёмно-серый |
| 1 | синий | 9 | ярко-синий |
| 2 | зелёный | 10 | ярко-зелёный |
| 3 | бирюзовый | 11 | ярко-бирюзовый |
| 4 | красный | 12 | ярко-красный |
| 5 | малиновый | 13 | ярко-малиновый |
| 6 | коричневый | 14 | жёлтый |
| 7 | светло-серый | 15 | белый |

Кроме них можно использовать **256 цветов** современных терминалов
(палитра xterm) — они хранятся в старших битах того же числа.

**Как получить цвет.** Функции из модуля `tvision::color`:

```rust
use tvision::color::*;

fn colors() {
    let a = attr(14, 1); // жёлтый на синем, из 16 цветов
    assert_eq!(a, 0x1E);
    assert_eq!((fore(a), back(a)), (14, 1)); // разобрать обратно
    assert_eq!(with_back(a, 4), 0x4E); // тот же текст на красном

    let b = attr256(208, 236); // оранжевый на тёмно-сером, из 256 цветов
    assert_eq!((fg256(b), bg256(b)), (208, 236));

    let c = rgb256(0xFFD700, 0x303030); // ближайшие к цветам RGB
    assert_eq!(fg256(c), 220);
}
```

**Чаще всего нужны:**

| Функция | Что делает |
|---------|-----------|
| `attr(текст, фон)` | цвет из 16 основных (номера 0–15) |
| `attr256(текст, фон)` | цвет из 256 (номера 0–255) |
| `rgb256(0xRRGGBB, 0xRRGGBB)` | ближайшие из 256 к цветам RGB |
| `with_fore(a, c)`, `with_back(a, c)` | заменить цвет текста / фона |
| `fore(a)`, `back(a)` | номер цвета текста / фона (0–15) |

**Реже нужны:** `fg256`, `bg256`, `is_fg256`, `is_bg256` (номера из 256);
`with_fg256`, `with_bg256`; `bios`, `to_bios` (свести к 16 цветам);
`xterm_rgb`, `rgb_to_xterm`, `xterm_to_bios`, `bios_to_ansi`,
`ansi_to_bios` (переводы между системами цветов); `fg_rgb`, `bg_rgb`
(цвет в RGB; второй аргумент — `VGA_RGB` или `GRUVBOX_RGB`);
`contrast256` (чёрный или белый — что читается на фоне); `shade_bg`
(фон «чуть темнее» — для полосатых таблиц); `remap` (перекрасить
палитру). Константы: `FG_256`, `BG_256`, `ERROR_ATTR`, `SHADOW_ATTR`,
`SHADOW_ATTR_256`, `VGA_RGB`, `GRUVBOX_RGB`.

**Что важно знать.** Обычно цвета **не задают числами**, а берут из
палитры по номеру (`dc.color(1)` в методе `draw`) — так программа
выглядит единообразно и её можно перекрасить. Свои числа нужны для
особых случаев: красная надпись «Ошибка», раскраска строк таблицы.

### `AttrPair` — пара цветов

**Что это.** Два цвета в одном числе (`u64`): обычный и **выделенный**.
Нужен для текстов с горячей буквой (`"~Ф~айл"`): буква между тильдами
рисуется вторым цветом. Создать — `color::pair(обычный, выделенный)`;
разобрать — `lo(p)`, `hi(p)`, `unpair(p)`.

## `ColorMode` — сколько цветов у терминала

**Что это.** `ColorMode::Ansi16` (16 цветов) или `ColorMode::Xterm256`
(256 цветов). Библиотека определяет режим сама по переменным окружения
терминала; если терминал умеет только 16, цвета из 256 заменяются
ближайшими.

```rust
use tvision::color::{color_mode, set_color_mode, ColorMode};

fn force_16() {
    set_color_mode(Some(ColorMode::Ansi16)); // всегда 16 цветов
    assert_eq!(color_mode(), ColorMode::Ansi16);
    set_color_mode(None); // снова определять самому
}
```

Функции: `color_mode()` — текущий режим, `set_color_mode(Some(…))` —
задать, `set_color_mode(None)` — определять самому, `detect_color_mode()`
— определить заново, `color_mode_from(…)` — то же по заданным строкам
(для тестов). Без изменения программы режим задаёт переменная окружения
`TVISION_COLORS=16` или `TVISION_COLORS=256`.

## Палитры

**Что это.** Палитра — список **номеров цветов**. У каждого вида
представления своя палитра: кнопка говорит «мне цвет номер 1», её
палитра переводит это в номер цвета диалога, палитра диалога — в номер
цвета программы, и только **палитра программы** хранит настоящие цвета.

Зачем так: одна и та же кнопка правильно выглядит и в сером диалоге, и в
синем окне, а чтобы перекрасить всю программу, достаточно поменять одну
палитру.

**Где лежат.** Модуль `tvision::color::palettes`:

| Константа | Что |
|-----------|-----|
| `GRUVBOX` | палитра программы по умолчанию — 256 цветов, тема gruvbox |
| `APP_COLOR` | классические цвета Borland (синий рабочий стол, серые диалоги) |
| `APP_BLACK_WHITE`, `APP_MONOCHROME` | чёрно-белая и монохромная |
| `BLUE_WINDOW`, `CYAN_WINDOW`, `GRAY_WINDOW` | палитры окон |
| `GRAY_DIALOG`, `BLUE_DIALOG`, `CYAN_DIALOG` | палитры диалогов |
| `BUTTON`, `INPUT_LINE`, `STATIC_TEXT`, `LABEL`, `CLUSTER`, `LIST_VIEWER`, `SCROLL_BAR`, `SCROLLER`, `EDITOR`, `MEMO`, … | палитры элементов — их удобно брать для своих представлений |

```rust
use tvision::*;

fn classic(app: &mut Program) {
    // Классические цвета Turbo Vision вместо gruvbox.
    app.palette = color::palettes::APP_COLOR.to_vec();
}
```

Палитра программы — обычный `Vec` в поле `app.palette`: её можно менять
на ходу (это делает диалог цветов `ColorDialog`) и сохранять в файл.

## `Cell` — клетка экрана

**Что это.** Символ и его цвет: поля `ch: char` и `attr: Attr`.
`Cell::new(символ, цвет)`. У иероглифов и эмодзи, которые занимают две
клетки, вторая клетка хранит `'\0'` (`is_wide_tail()` — `true`).

## `DrawBuffer` — строка для рисования

**Что это.** Одна строка клеток, которую сначала заполняют, а потом
целиком выводят: `dc.write_line(x, y, ширина, высота, &буфер)`. Удобна,
когда в строке несколько кусков разного цвета.

**Аналог:** `TDrawBuffer`.

```rust
use tvision::*;

/// «[ OK ]  Сохранить» с выделенной буквой «С».
fn line(width: usize) -> DrawBuffer {
    let mut b = DrawBuffer::new(width); // пробелы
    b.move_char(0, ' ', 0x70, width); // залить серым
    let x = b.move_str(0, "[ OK ]", 0x2F); // вернёт ширину: 6
    b.move_cstr(x + 2, "~С~охранить", color::pair(0x70, 0x7E)); // «С» — вторым цветом
    b
}
```

| Метод | Что делает |
|-------|-----------|
| `DrawBuffer::new(ширина)` | строка из пробелов |
| `move_char(x, символ, цвет, сколько)` | повторить символ |
| `move_str(x, текст, цвет)` | написать текст; возвращает его **ширину** |
| `move_str_limited(x, текст, цвет, макс)` | не шире `макс` клеток |
| `move_cstr(x, текст, пара)` | текст с горячей буквой в тильдах |
| `put_char(x, c)`, `put_attribute(x, цвет)` | поменять только символ / только цвет |
| `move_buf(x, &клетки, цвет)` | скопировать готовые клетки |

Цвет `0` в `move_str` и `move_char` значит «не менять цвет»: так пишут
текст поверх уже закрашенного фона.

## `ScreenBuffer` — весь экран

**Что это.** Все клетки экрана. Программа рисует кадр в него, а потом
выводит в терминал только то, что изменилось. В своём коде нужен в
основном в тестах:

```rust
use tvision::*;

fn check_frame(app: &Program) {
    let s: &ScreenBuffer = app.screen();
    let top = s.line_text(0); // первая строка экрана текстом
    let cell = s.get(2, 0); // клетка (x = 2, y = 0)
    let _ = (top, cell.attr, s.to_text(), s.width, s.height);
}
```

Методы: `ScreenBuffer::new(ш, в)`, `get(x, y)`, `get_mut(x, y)`,
`clear(цвет)`, `line_text(y)`, `to_text()`; поля `width`, `height`,
`cells`. Удобнее всего — `app.screen_text()`: весь экран одной строкой.

## Функции текста

Модуль `tvision::text`. Нужны, чтобы считать **ширину на экране** —
она не всегда равна числу символов: иероглифы занимают две клетки, а
тильды в `"~Ф~айл"` не рисуются вовсе.

```rust
use tvision::text::*;

fn texts() {
    assert_eq!(str_width("Привет"), 6);
    assert_eq!(str_width("漢字"), 4); // по две клетки
    assert_eq!(cstr_width("~Ф~айл"), 4); // тильды не считаются
    assert_eq!(strip_tildes("~Ф~айл"), "Файл");
    assert_eq!(hotkey("~Ф~айл"), Some('Ф'));
    assert!(same_hotkey('a', 'Ф')); // Alt+A в латинской раскладке = Alt+Ф
    assert_eq!(truncate_width("Привет, мир", 6), "Привет");
    assert_eq!(wrap_text("один два три", 8), vec!["один два", "три"]);
}
```

| Функция | Что делает |
|---------|-----------|
| `str_width(s)` | ширина строки в клетках |
| `char_width(c)` | ширина символа: 0, 1 или 2 |
| `cstr_width(s)` | ширина без тильд |
| `strip_tildes(s)` | убрать тильды |
| `hotkey(s)` | горячая буква (в верхнем регистре) |
| `same_hotkey(нажата, горячая)` | совпадает ли буква с учётом раскладки (й↔q, ф↔a) |
| `truncate_width(s, макс)` | начало строки не шире `макс` клеток |
| `wrap_text(s, ширина)` | разбить на строки по словам |
| `to_upper(c)` | заглавная буква (и кириллица) |

> Ширину на экране считайте `str_width`, а не `s.len()` (это байты: у
> «Привет» их 12) и не `s.chars().count()`.
