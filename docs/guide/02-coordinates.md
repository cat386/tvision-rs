## Ячейки и оси

Единица измерения — **ячейка** терминала: одна строка в высоту, один
символ в ширину. Пикселей нет.

```text
      x →   0 1 2 3 4 5 6 7 …
  y   0     ┌─────────────
  ↓   1     │
      2     │      ● (5, 2)
```

* `x` — номер **столбца**, растёт вправо, начинается с 0;
* `y` — номер **строки**, растёт **вниз**, начинается с 0;
* `Point { x, y }` — точка; тот же тип служит **размером** (`x` — ширина,
  `y` — высота): `ViewState::size`, `Rect::size()`;
* координаты — `i32`, могут быть отрицательными: окно можно утащить за
  левый край экрана, его `origin.x` станет меньше нуля.

## Прямоугольник: правая граница не входит

`Rect { a, b }` — левый верхний угол `a` **включительно** и правый нижний
`b` **не включительно** (как диапазон `a..b` в Rust):

```text
   Rect::new(2, 1, 7, 4)

      0 1 2 3 4 5 6 7 8
   0  . . . . . . . . .
   1  . . ■ ■ ■ ■ ■ . .     столбцы 2..=6, строки 1..=3
   2  . . ■ ■ ■ ■ ■ . .     ширина  = 7 - 2 = 5
   3  . . ■ ■ ■ ■ ■ . .     высота  = 4 - 1 = 3
   4  . . . . . . . . .     (7, 4) — уже снаружи
```

Отсюда правила, которые стоит запомнить:

* **ширина = `b.x - a.x`**, без «+1»;
* элемент высотой в одну строку на строке `y`: `Rect::new(x, y, x + w, y + 1)`;
* прямоугольники `(0,0)-(5,1)` и `(5,0)-(10,1)` **стыкуются**, не
  перекрываясь;
* `contains(p)` — `a.x <= p.x < b.x` и `a.y <= p.y < b.y`;
* `is_empty()` — ширина или высота ≤ 0.

```rust
use tvision::*;

fn rect_rules() {
    let r = Rect::new(2, 1, 7, 4);
    assert_eq!((r.width(), r.height()), (5, 3));
    assert!(r.contains(Point::new(6, 3))); // последняя ячейка
    assert!(!r.contains(Point::new(7, 3))); // правый край — снаружи

    // Строка ввода шириной 20 на строке 2 начиная со столбца 10:
    let field = Rect::new(10, 2, 10 + 20, 2 + 1);
    assert_eq!(field.size(), Point::new(20, 1));

    // Соседи стыкуются без зазора и без наложения.
    let left = Rect::new(0, 0, 5, 1);
    let right = Rect::new(5, 0, 10, 1);
    assert!(left.intersect(&right).is_empty());

    // Сжать на рамку: по 1 клетке с каждой стороны.
    assert_eq!(Rect::new(0, 0, 40, 10).grown(-1, -1), Rect::new(1, 1, 39, 9));
    // Сдвинуть: размер не меняется.
    assert_eq!(r.moved(3, -1), Rect::new(5, 0, 10, 3));
}
```

Так же устроен и оригинальный Turbo Vision (`TRect`), поэтому числа из
программ на C++ и Pascal переносятся без изменений.

## Три системы координат

У каждой точки на экране три «адреса»:

1. **Экранные** (абсолютные) — от левого верхнего угла терминала.
2. **Координаты владельца** — от левого верхнего угла группы, в которой
   лежит представление. В них задаются границы представления:
   `vs.origin` и `Rect` в конструкторе.
3. **Свои** (локальные) — от левого верхнего угла самого представления;
   его левый верхний угол — `(0, 0)`. В них идёт рисование.

```text
 Экран 80×25
 ┌──────────────────────────────────────────────────────────────┐ y=0  строка меню
 │░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░│ y=1  ← рабочий стол: его (0,0)
 │░░░░ ╔═══════════ Окно ═══════════╗ ░░░░░░░░░░░░░░░░░░░░░░░░░░│ y=3  ← окно: origin (4,2) у стола
 │░░░░ ║  Имя: [кнопка...]          ║ ░░░░░░░░░░░░░░░░░░░░░░░░░░│ y=4  ← кнопка: origin (7,1) у окна
 │░░░░ ╚════════════════════════════╝ ░░░░░░░░░░░░░░░░░░░░░░░░░░│
 └──────────────────────────────────────────────────────────────┘ y=24 строка состояния

  Левый верхний угол кнопки:
    своё       (0, 0)
    у окна     (7, 1)                      ← Rect, переданный в Button::new
    у стола    (4 + 7, 2 + 1)  = (11, 3)
    на экране  (11, 3 + 1)     = (11, 4)   ← стол начинается со строки 1
```

Цепочка вложения: **программа** (её начало совпадает с экраном) →
**рабочий стол** (под строкой меню) → **окно** → элемент (а внутри
группы — ещё глубже). На каждом уровне начало координат сдвигается на
`origin` группы.

## Кто в каких координатах

| Что | Система |
|-----|---------|
| `vs.origin`, `vs.bounds()`, `Rect` в конструкторе элемента | **владельца** |
| `vs.extent()` | **своя**: `(0,0)`–`size` |
| всё рисование: `DrawCtx::write_str`, `fill`, `write_line`… | **своя** |
| `vs.cursor` (текстовый курсор) | **своя** |
| `MouseEvent::pos` в `View::handle_event` | **владельца** — переводите `vs.make_local(m.pos)` |
| `MouseEvent::pos` в `AppHandler::handle_event` | **экранная** |
| границы окна для `app.insert_window(w)` | **рабочего стола** |
| `app.desktop().group.vs.extent()` | рабочего стола: весь стол от `(0,0)` |
| элемент в `Dialog::add` / `Window::add` | **окна**, рамка — строка 0 и столбец 0 |
| `ctx.popup_menu(menu, pos)` | **экранная** |
| `ctx.screen_size`, `app.screen()` | экран целиком |
| `Window::interior()` | **своя** у окна — и одновременно координаты для детей окна |
| `Editor::cursor()`, `Pos { line, col }` | **текста**: строка и номер символа, не ячейки экрана |
| `Scroller::delta`, `Table::cursor()` | **содержимого**: номер строки/столбца данных |

Последние две строки — не экранные координаты вовсе; о них — в разделах
про [прокрутку](#прокрутка-координаты-содержимого) и
[широкие символы](#широкие-символы-символ--ячейка).

## Переводы между системами

| Из → в | Как |
|--------|-----|
| владельца → своя | `vs.make_local(p)` = `p - vs.origin` |
| своя → владельца | `p + vs.origin` |
| своя → экранная | начало владельца на экране + `vs.origin` + `p` (функция ниже) |
| экранная → своя | обратное вычитание |

Начало координат **владельца** любого представления относительно
программы (то есть на экране) даёт `app.group.owner_origin_of(id)`, а
границы в координатах владельца — `app.group.geometry_of(id)`:

```rust
use tvision::platform::HeadlessBackend;
use tvision::*;

/// Границы представления на экране.
fn screen_rect(app: &Program, id: ViewId) -> Option<Rect> {
    let (bounds, _owner_size) = app.group.geometry_of(id)?; // у владельца
    let o = app.group.owner_origin_of(id)?; // где на экране начало владельца
    Some(bounds.moved(o.x, o.y))
}

fn layers() {
    let menu = Menu::new().submenu("~Ф~айл", Menu::new().item("~В~ыход", cm::QUIT));
    let mut app = Program::new(Box::new(HeadlessBackend::new(80, 25)), Some(menu), None);

    let mut w = Window::new(Rect::new(4, 2, 40, 12), "Окно", 1); // у рабочего стола
    let button = w.add(Button::new(Rect::new(7, 1, 19, 3), "O~K~", cm::OK, bf::DEFAULT)); // у окна
    let win = app.insert_window(w);

    assert_eq!(screen_rect(&app, win).unwrap().a, Point::new(4, 3)); // стол начинается со строки 1
    assert_eq!(screen_rect(&app, button).unwrap().a, Point::new(11, 4)); // 4+7, 2+1+1
}
```

Обычно переводить вручную не нужно: рисование всегда в своих
координатах, а мышь — в координатах владельца с готовым `make_local`.
Экранные координаты требуются для контекстного меню и для своих
всплывающих окон.

## Окно: рамка и внутренность

Рамка окна — его **внешние** строка и столбец с каждой стороны. Дети
окна задаются в координатах окна, поэтому рамка — это строка 0,
последняя строка, столбец 0 и последний столбец.

```text
   Window::new(Rect::new(0, 0, 30, 8), …)   — размер 30×8

      0         1         2
      0123456789012345678901234567890
   0  ╔══════════ Окно ═════════[■]╗    ← рамка: строка 0
   1  ║(1,1)                       ▲    ← interior() = (1,1)-(29,7)
   2  ║                            ▒    ← вертикальная полоса: x = 29, y = 1..7
   ⋮
   6  ║                            ▼
   7  ╚══◄▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒►═══╝    ← горизонтальная: y = 7, x = 2..28
```

| Что | Прямоугольник (в координатах окна размера `w`×`h`) |
|-----|------|
| всё окно (`win.group.vs.extent()`) | `(0, 0)–(w, h)` |
| внутренность (`win.interior()`) | `(1, 1)–(w-1, h-1)` |
| вертикальная полоса (`standard_scroll_bar(true)`) | `(w-1, 1)–(w, h-1)` — **на** рамке |
| горизонтальная полоса (`standard_scroll_bar(false)`) | `(2, h-1)–(w-2, h)` — **на** рамке |

Стандартные полосы прокрутки лежат прямо на рамке, поэтому
`interior()` остаётся целиком под содержимое. Если внутри несколько
частей, делите `interior()`:

```rust
use tvision::*;

/// Окно: список слева (треть ширины), разделитель, текст справа.
fn split_window(r: Rect) -> Window {
    let mut w = Window::new(r, "Две части", 1);
    let i = w.interior();
    let mid = i.a.x + i.width() / 3;
    let mut list = ListBox::new(Rect::new(i.a.x, i.a.y, mid, i.b.y), 1, None);
    list.vs.grow_mode = gf::GROW_HI_Y; // тянется только по высоте
    w.add(list);
    let mut sep = StaticText::new(Rect::new(mid, i.a.y, mid + 1, i.b.y), &"│".repeat(i.height() as usize));
    sep.vs.grow_mode = gf::GROW_HI_Y;
    w.add(sep);
    let mut text = StaticText::new(Rect::new(mid + 1, i.a.y, i.b.x, i.b.y), "Подробности…");
    text.vs.grow_mode = gf::GROW_HI_X | gf::GROW_HI_Y; // тянется в обе стороны
    w.add(text);
    w
}

fn split() {
    let w = split_window(Rect::new(0, 0, 32, 10)); // interior = (1,1)-(31,9), треть = 10
    let xs: Vec<i32> = w.group.children.iter().map(|c| c.vs().origin.x).collect();
    assert_eq!(&xs[xs.len() - 3..], &[1, 11, 12]);
}
```

У окна с `wf::GROW` пользователь может менять размер — поэтому раскладку
считают **от размеров**, а не числами, и задают `grow_mode` (см.
[ниже](#изменение-размера-grow_mode)).

## Диалог: раскладка элементов

Диалог — тоже окно: столбец 0 и строка 0 — рамка, элементы начинаются со
строки 1. Принятые в Turbo Vision отступы:

```text
   Dialog::centered(40, 11, "Знакомство")

      0         1         2         3
      0123456789012345678901234567890123456789
   0  ╔════════════ Знакомство ════════════[■]╗
   1  ║                                       ║
   2  ║ Имя:    [                           ] ║  ← Label (2,2)-(10,3), InputLine (10,2)-(38,3)
   3  ║                                       ║
   4  ║ Город:  [                           ] ║  ← через строку — чтобы не теснить
   5  ║                                       ║
   6  ║  (•) Да   ( ) Нет                     ║  ← Cluster (3,6)-(25,7)
   7  ║                                       ║
   8  ║        [  OK  ]     [ Отмена ]        ║  ← кнопки высотой 2: (8,8)-(18,10), (21,8)-(33,10)
   9  ║         ▀▀▀▀▀▀▀      ▀▀▀▀▀▀▀▀▀        ║  ← вторая строка кнопки — её тень
  10  ╚═══════════════════════════════════════╝
```

* поля — со столбца 2–3, правый край — за 2 клетки до рамки (`w - 2`);
* **кнопка занимает 2 строки** (текст и тень), её `Rect` — высотой 2;
* подпись `Label` стоит слева от поля на той же строке или над ним;
* значок `History` (3×1) ставится сразу справа от строки ввода;
* последняя строка с элементами — `h - 2` (строка `h - 1` — рамка).

Для однотипных строк удобна маленькая функция:

```rust
use tvision::*;

/// Строка «подпись: поле» на строке `y` диалога шириной `w`.
fn field_row(d: &mut Dialog, y: i32, w: i32, label: &str, max_len: usize) -> ViewId {
    let label_w = 10;
    let id = d.add(InputLine::new(Rect::new(2 + label_w, y, w - 2, y + 1), max_len));
    d.add(Label::new(Rect::new(2, y, 2 + label_w, y + 1), label, Some(id)));
    id
}

fn form() -> Dialog {
    let (w, h) = (44, 11);
    let mut d = Dialog::centered(w, h, "Адрес");
    for (i, l) in ["~Г~ород:", "~У~лица:", "~Д~ом:"].iter().enumerate() {
        field_row(&mut d, 2 + 2 * i as i32, w, l, 60);
    }
    // Две кнопки по центру внизу: ширина 12, промежуток 2.
    let bw = 12;
    let x0 = (w - (2 * bw + 2)) / 2;
    d.add(Button::new(Rect::new(x0, h - 3, x0 + bw, h - 1), "O~K~", cm::OK, bf::DEFAULT));
    d.add(Button::new(Rect::new(x0 + bw + 2, h - 3, x0 + 2 * bw + 2, h - 1), "Отмена", cm::CANCEL, bf::NORMAL));
    d
}

fn form_fits() {
    let d = form();
    let size = d.win.group.vs.size;
    let inner = Rect::new(1, 1, size.x - 1, size.y - 1);
    for c in &d.win.group.children {
        let b = c.vs().bounds();
        assert!(inner.intersect(&b) == b, "{:?} залезает на рамку", b);
    }
}
```

Проверка `form_fits` — полезный приём для своих тестов: ни один элемент
не должен залезать на рамку.

## Рабочий стол и экран

Окна вставляются на **рабочий стол**, поэтому их границы — в координатах
стола, а не экрана. Стол занимает экран между строкой меню и строкой
состояния:

| Есть меню | Есть строка состояния | Стол на экране 80×25 |
|-----------|-----------------------|----------------------|
| да | да | строки 1–23, размер 80×23 |
| да | нет | строки 1–24, размер 80×24 |
| нет | да | строки 0–23, размер 80×24 |
| нет | нет | весь экран |

Поэтому размер окна «во весь стол» берите у стола, а не у экрана:

```rust
use tvision::*;

/// Два окна рядом во весь рабочий стол: 2/5 и 3/5 ширины.
fn side_by_side(app: &mut Program) {
    let r = app.desktop().group.vs.extent(); // (0,0)-(ширина, высота) стола
    let mid = r.b.x * 2 / 5;
    app.insert_window(Window::new(Rect::new(0, 0, mid, r.b.y), "Слева", 1));
    app.insert_window(Window::new(Rect::new(mid, 0, r.b.x, r.b.y), "Справа", 2));
}
```

Размер экрана — `app.ctx.screen_size` (в представлении — `ctx.screen_size`).
При изменении размера терминала программа сама меняет размеры стола,
меню и строки состояния, а окна подстраиваются по `grow_mode`.

## Центрирование

* `Dialog::centered(w, h, title)` ставит флаг `of::CENTERED`, и диалог
  центрируется **в момент вставки** — относительно размера того, куда
  вставляют (рабочего стола).
* Для любого представления: `vs.options |= of::CENTER_X` (по горизонтали),
  `of::CENTER_Y` (по вертикали), `of::CENTERED` (оба). Координаты,
  переданные в `Rect`, при этом заменяются.
* Вручную: `x = (ширина_владельца - ширина) / 2`.

```rust
use tvision::platform::HeadlessBackend;
use tvision::*;

fn centering() {
    // Меню и строка состояния: стол 80×23 (строки 1..23 экрана).
    let status = vec![StatusDef::all(vec![StatusItem::new("~Alt-X~ Выход", kb::ALT_X, cm::QUIT)])];
    let menu = Menu::new().submenu("~Ф~айл", Menu::new().item("~В~ыход", cm::QUIT));
    let mut app = Program::new(Box::new(HeadlessBackend::new(80, 25)), Some(menu), Some(status));
    assert_eq!(app.desktop().group.vs.size, Point::new(80, 23));

    let id = app.insert_window(Dialog::centered(40, 9, "По центру"));
    let o = app.find::<Dialog>(id).unwrap().win.group.vs.origin;
    assert_eq!(o, Point::new((80 - 40) / 2, (23 - 9) / 2)); // (20, 7) у стола, (20, 8) на экране
}
```

Центрирование происходит **один раз** — при вставке. Если диалог должен
оставаться по центру при изменении размера терминала, задайте
`grow_mode = gf::GROW_REL` (окно сохраняет относительное положение).

## Изменение размера: `grow_mode`

Когда владелец меняет размер на `Δ = (dx, dy)` (окно растянули мышью, F5,
терминал стал больше), каждый ребёнок сдвигает свои края по флагам
`vs.grow_mode`:

| Флаг | Край | Сдвиг |
|------|------|-------|
| `gf::GROW_LO_X` | левый | `+dx` |
| `gf::GROW_LO_Y` | верхний | `+dy` |
| `gf::GROW_HI_X` | правый | `+dx` |
| `gf::GROW_HI_Y` | нижний | `+dy` |
| `gf::GROW_REL` | все | пропорционально размеру владельца |

```text
                     до                          после растяжения на (+6, +2)
  0                  ┌──────────────┐            ┌────────────────────┐
  GROW_HI_X|HI_Y     │▓▓▓▓▓▓▓▓      │            │▓▓▓▓▓▓▓▓▓▓▓▓▓▓      │   тянется
                     │▓▓▓▓▓▓▓▓      │            │▓▓▓▓▓▓▓▓▓▓▓▓▓▓      │
  GROW_LO_Y|HI_Y|HI_X│              │            │                    │
     (строка внизу)  │====== инфо   │            │                    │
                     │      [ OK ]  │            │============ инфо   │   едет вниз, тянется вбок
  GROW_ALL           └──────────────┘            │            [ OK ]  │   едет с правым нижним углом
                                                 └────────────────────┘
```

| Что нужно | `grow_mode` |
|-----------|-------------|
| растягиваться вместе с окном (список, таблица, редактор) | `GROW_HI_X \| GROW_HI_Y` |
| оставаться на месте с фиксированным размером | `0` (по умолчанию у большинства элементов) |
| прижаться к низу, растягиваясь по ширине (строка сведений) | `GROW_LO_Y \| GROW_HI_Y \| GROW_HI_X` |
| прижаться к правому нижнему углу (кнопка OK) | `GROW_ALL` |
| прижаться к правому краю (вертикальная полоса) | `GROW_LO_X \| GROW_HI_X \| GROW_HI_Y` |

```rust
use tvision::*;

fn grow() {
    // Владелец вырос на (+6, +2): с 30×10 до 36×12.
    let owner = Point::new(36, 12);
    let delta = Point::new(6, 2);
    let mut info = StaticText::new(Rect::new(1, 7, 29, 8), "инфо");
    info.vs.grow_mode = gf::GROW_LO_Y | gf::GROW_HI_Y | gf::GROW_HI_X;
    assert_eq!(view::calc_bounds(&info, delta, owner), Rect::new(1, 9, 35, 10)); // вниз на 2, шире на 6

    let mut ok = Button::new(Rect::new(17, 7, 29, 9), "O~K~", cm::OK, bf::DEFAULT);
    ok.vs.grow_mode = gf::GROW_ALL;
    assert_eq!(view::calc_bounds(&ok, delta, owner), Rect::new(23, 9, 35, 11)); // едет в угол
}
```

Что растягивается само, а что — нет:

| Элемент | `grow_mode` по умолчанию |
|---------|--------------------------|
| `Editor`, `TreeView`, `Outline`, `DualPanel` | `GROW_HI_X \| GROW_HI_Y` — тянутся |
| полосы `ScrollBar` (и `standard_scroll_bar`) | прижаты к своему краю |
| `Table`, `ListBox`, `FilePanel`, `InputLine`, кнопки, тексты и остальное | `0` — **не меняются**: задайте сами |

```rust
use tvision::*;

fn table_in_window(w: &mut Window, model: Box<dyn TableModel>, v: ViewId, h: ViewId) {
    let mut t = Table::new(w.interior(), model, Some(v), Some(h));
    t.vs.grow_mode = gf::GROW_HI_X | gf::GROW_HI_Y; // иначе при F5 таблица останется маленькой
    w.add(t);
}
``` Наименьший и наибольший
размер окна — `View::size_limits` (у окна по умолчанию не меньше
`window::MIN_WIN_SIZE` = 16×6).

## Мышь

Пока событие мыши спускается по дереву, каждая группа **вычитает своё
начало** — поэтому до представления позиция доходит **в координатах его
владельца**, той же системе, что и `vs.origin`. Перевести в свои
координаты — `vs.make_local(m.pos)`:

```rust
use std::cell::Cell;
use std::rc::Rc;
use tvision::platform::HeadlessBackend;
use tvision::*;

/// Запоминает, куда (в своих координатах) по нему щёлкнули.
struct Probe {
    vs: ViewState,
    last: Rc<Cell<Option<Point>>>,
}

impl View for Probe {
    tvision::impl_view_basics!();
    fn draw(&self, dc: &mut DrawCtx) {
        let a = dc.color(1);
        dc.fill(self.vs.extent(), '·', a);
    }
    fn handle_event(&mut self, ev: &mut Event, _ctx: &mut Ctx) {
        if let Event::MouseDown(m) = ev {
            self.last.set(Some(self.vs.make_local(m.pos))); // владелец → своя
            ev.clear();
        }
    }
}

fn mouse_chain() {
    let last = Rc::new(Cell::new(None));
    let mut b = HeadlessBackend::new(80, 25);
    b.push_click(14, 6); // экранные координаты
    let menu = Menu::new().submenu("~Ф~айл", Menu::new().item("~В~ыход", cm::QUIT));
    let mut app = Program::new(Box::new(b), Some(menu), None);

    let mut w = Window::new(Rect::new(4, 2, 40, 12), "Окно", 1); // окно у стола: (4,2) → экран (4,3)
    w.add(Probe { vs: ViewState::new(Rect::new(5, 2, 20, 5)), last: last.clone() }); // у окна: (5,2) → экран (9,5)
    app.insert_window(w);
    app.pump(&mut program::NoHandler);

    assert_eq!(last.get(), Some(Point::new(14 - 9, 6 - 5))); // (5, 1)
}
```

* В `AppHandler::handle_event` позиция **экранная** — программа ничего
  не вычитает. Поэтому контекстное меню из обработчика приложения
  открывается прямо в `m.pos`.
* Из представления контекстное меню требует экранную точку: сложите
  начало владельца на экране и `m.pos` (функция [`screen_rect`](#переводы-между-системами)
  или сохранённое заранее начало).
* Во время протяжки (`ctx.grab_mouse(id)`) события достаются вам, даже
  когда мышь вне ваших границ: локальные координаты тогда бывают
  отрицательными или больше размера — ограничивайте их (`clamp`).

## Рисование

`DrawCtx` — всегда в **своих** координатах: `(0, 0)` — левый верхний
угол представления, `dc.size` — его размер. Всё, что выходит за границы
(или закрыто другими окнами), обрезается само — ни проверять, ни
переводить в экранные координаты не нужно.

```rust
use tvision::*;

/// Рамка по краю своего прямоугольника и подпись по центру.
fn frame_and_title(dc: &mut DrawCtx, title: &str) {
    let a = dc.color(1);
    let (w, h) = (dc.size.x, dc.size.y);
    dc.fill(Rect::new(0, 0, w, h), ' ', a); // вся своя область
    dc.write_char(0, 0, '┌', a, 1);
    dc.write_char(1, 0, '─', a, (w - 2).max(0));
    dc.write_char(w - 1, 0, '┐', a, 1); // последний столбец — w - 1, не w
    dc.write_char(0, h - 1, '└', a, 1);
    dc.write_char(1, h - 1, '─', a, (w - 2).max(0));
    dc.write_char(w - 1, h - 1, '┘', a, 1);
    let tw = text::str_width(title) as i32;
    dc.write_str((w - tw) / 2, h / 2, title, a);
}
```

Последний столбец своей области — `size.x - 1`, последняя строка —
`size.y - 1`. Представление обязано закрасить **всю** свою область:
что не нарисовано, останется от предыдущего кадра.

## Прокрутка: координаты содержимого

У прокручиваемых представлений две системы: **экранная** (строка `y`
внутри представления, `0..size.y`) и **содержимого** (номер строки
данных). Их связывает смещение прокрутки:

```text
  данные                 представление (size.y = 4)
  строка 0
  строка 1
  строка 2  ← top/delta.y = 2 ─┐  y = 0
  строка 3                     │  y = 1
  строка 4                     │  y = 2
  строка 5                    ─┘  y = 3
  строка 6
```

* строка данных = `top + y`; экранная строка = `строка_данных - top`;
* столбец данных = `delta.x + x` (горизонтальная прокрутка);
* при щелчке: `let row = top + vs.make_local(m.pos).y`.

`Scroller` хранит смещение в `delta`, `Table` и `TreeView` — внутри и
отдают **строку данных** (`cursor()`, `cursor_row()`), а не экранную.
Пример своего прокручиваемого представления — [`Scroller`](17-data-views.md#scroller).

## Широкие символы: символ ≠ ячейка

Большинство символов, включая кириллицу, занимает одну ячейку, но
иероглифы и многие эмодзи — **две**, а комбинирующие знаки — ноль.
Поэтому «номер символа» и «экранный столбец» — разные вещи:

```rust
use tvision::*;

fn widths() {
    let s = "Да漢字!";
    assert_eq!(s.chars().count(), 5); // символов
    assert_eq!(text::str_width(s), 7); // ячеек: Д а 漢漢 字字 !
    // Кнопка или поле должны быть шириной по ячейкам, а не по символам.
    let w = text::str_width("Сохранить") as i32;
    let _r = Rect::new(2, 2, 2 + w + 4, 4);
}
```

* для ширины на экране — `text::str_width(s)`, для C-строк с тильдами —
  `text::cstr_width(s)`; не `s.len()` (байты!) и не `chars().count()`;
* обрезать по ширине — `text::truncate_width(s, max)`;
* `DrawBuffer::move_str` возвращает **ширину** записанного — следующую
  надпись ставьте с `x + ширина`;
* у редактора позиция `Pos { line, col }` — номер **символа**; экранный
  столбец с учётом табуляций и широких символов дают
  `editor.col_to_x(line, col)` и обратно `x_to_col(line, x)`.

## Курсор

Текстовый курсор задаётся в **своих** координатах: `vs.set_cursor(x, y)`
и `vs.show_cursor()`; виден он только у представления в фокусе.
Программа сама переводит его в экранные координаты и прячет, если он
закрыт другим окном или вне видимой области.

## Частые ошибки

| Симптом | Причина | Исправление |
|---------|---------|-------------|
| элемент на клетку шире/уже | ширину считали как `b.x - a.x + 1` | правая граница не входит: `Rect::new(x, y, x + w, y + 1)` |
| элемент налез на рамку окна | начали с 0 или закончили на `w` | первая свободная клетка — 1, последняя — `w - 2` (`interior()`) |
| у кнопки «отрезана» тень | высота `Rect` кнопки 1 | у кнопки высота 2 |
| щелчок «промахивается» на величину окна | сравнивали `m.pos` с `vs.extent()` | сначала `vs.make_local(m.pos)` |
| контекстное меню не там | передали локальную точку | `popup_menu` ждёт экранную |
| окно «во весь экран» вылезает под строку состояния | размер взяли у экрана | у рабочего стола: `app.desktop().group.vs.extent()` |
| диалог не по центру после изменения размера терминала | центрирование — только при вставке | `grow_mode = gf::GROW_REL` |
| при растягивании окна элемент остаётся маленьким | не задан `grow_mode` | `gf::GROW_HI_X \| gf::GROW_HI_Y` |
| текст с иероглифами вылезает за поле | ширину считали в символах | `text::str_width`, `truncate_width` |
| последняя строка/столбец не рисуется или рисуется за краем | рисовали в `size.x` | последний столбец — `size.x - 1` |
