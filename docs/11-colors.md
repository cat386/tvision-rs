# 11. Цвета и палитры

## Атрибут

Цвет ячейки — атрибут `Attr` (`u32`). Его младший байт устроен, как в
BIOS и оригинальном Turbo Vision: младшие 4 бита — цвет текста, старшие
4 бита — цвет фона.

| № | Цвет | № | Цвет |
|---|------|---|------|
| 0 | чёрный | 8 | тёмно-серый |
| 1 | синий | 9 | ярко-синий |
| 2 | зелёный | 10 | ярко-зелёный |
| 3 | бирюзовый | 11 | ярко-бирюзовый |
| 4 | красный | 12 | ярко-красный |
| 5 | малиновый | 13 | ярко-малиновый |
| 6 | коричневый | 14 | жёлтый |
| 7 | светло-серый | 15 | белый |

`0x1E` — жёлтый (14) на синем (1), `0x70` — чёрный на сером, `0x2F` —
белый на зелёном. Такие числа по-прежнему годятся везде, где нужен
атрибут.

```rust
use tvision::*;

fn attrs() {
    let a = color::attr(14, 1); // == 0x1E
    assert_eq!(color::fore(a), 14);
    assert_eq!(color::back(a), 1);
}
```

### 256 цветов

Кроме 16 цветов BIOS, текст и фон могут быть любым из **256 цветов
палитры xterm** (как `TColorXTerm` в magiblot/tvision):

| Номера | Что |
|--------|-----|
| 0–15 | 16 основных цветов (в порядке ANSI: 1 — красный, 4 — синий) |
| 16–231 | куб 6×6×6: `16 + 36·r + 6·g + b`, где r, g, b — от 0 до 5 |
| 232–255 | 24 оттенка серого от `#080808` до `#EEEEEE` |

```rust
use tvision::color::*;

fn colors256() {
    let a = attr256(208, 236); // оранжевый на тёмно-сером
    assert_eq!((fg256(a), bg256(a)), (208, 236));

    let b = with_bg256(0x1E, 24); // жёлтый текст BIOS на xterm-фоне 24
    assert!(!is_fg256(b) && is_bg256(b));

    let c = rgb256(0xFFD700, 0x303030); // ближайшие к RGB цвета xterm
    assert_eq!(fg256(c), 220);
}
```

Как атрибут хранит цвета:

| Биты | Что хранят |
|------|-----------|
| 0–3 | цвет текста BIOS |
| 4–7 | цвет фона BIOS |
| 8–15 | номер цвета текста xterm, если стоит флаг `FG_256` |
| 16–23 | номер цвета фона xterm, если стоит флаг `BG_256` |
| 24, 25 | флаги `color::FG_256`, `color::BG_256` |

У 256-цветного атрибута младший байт всегда содержит **ближайший цвет
BIOS**. Его показывает терминал, который умеет только 16 цветов, и его
видит старый код, читающий `attr & 0x0F` или `fore(a)`.

| Функция | Что делает |
|---------|-----------|
| `attr(fg, bg)` | атрибут BIOS (0–15) |
| `attr256(fg, bg)` | атрибут из номеров xterm (0–255) |
| `with_fg256(a, n)`, `with_bg256(a, n)` | заменить цвет текста / фона номером xterm |
| `with_fore(a, c)`, `with_back(a, c)` | заменить цвет текста / фона цветом BIOS |
| `rgb256(fg, bg)` | ближайшие к `0xRRGGBB` цвета xterm |
| `fore(a)`, `back(a)` | цвет BIOS (для 256-цветного — приближение) |
| `fg256(a)`, `bg256(a)` | номер xterm (для цвета BIOS — 0–15 в порядке ANSI) |
| `is_fg256(a)`, `is_bg256(a)` | задан ли цвет номером xterm |
| `to_bios(a)` | свести к 16 цветам |
| `xterm_rgb(n)`, `rgb_to_xterm(rgb)`, `xterm_to_bios(n)` | переводы между номерами xterm, RGB и BIOS |
| `fg_rgb(a, &base)`, `bg_rgb(a, &base)` | цвет в RGB (`base` — RGB 16 цветов BIOS; так рисует tvision-gui) |
| `contrast256(n)` | чёрный (16) или белый (231) — читаемый текст на фоне `n` |
| `shade_bg(a)` | чуть другой фон — для «зебры» |
| `remap(palette, &map)` | перекрасить палитру: цвет BIOS `i` → xterm `map[i]` |

### Пара атрибутов

`AttrPair` (`u64`) — пара атрибутов для C-строк
(`DrawBuffer::move_cstr`): обычный цвет и цвет текста между `~`.
Пару даёт `dc.get_color(0x0301)`, собирает `color::pair(обычный,
подсветка)`, разбирают `color::lo(p)` и `color::hi(p)`. Старая запись
пары из двух байтов BIOS (`0x7470` — обычный `0x70`, подсветка `0x74`)
тоже понимается.

Особые атрибуты: `color::ERROR_ATTR` (`0xCF`, белый на красном — ошибка
палитры, см. ниже) и `color::SHADOW_ATTR` (`0x08`, тень).

## Цепочка палитр

Представления не используют атрибуты напрямую — иначе один и тот же
элемент выглядел бы одинаково и в синем окне, и в сером диалоге. В
`draw` используются **номера цветов**:

```text
StaticText::palette()      = [6]          ← цвет №1 текста = цвет №6 владельца
Dialog (GRAY_DIALOG)       = [32, 33, … ] ← цвет №6 диалога = №37 приложения
Program::palette (APP_COLOR)[37 − 1] = 0x70 ← настоящий атрибут: чёрный на сером
```

`dc.color(1)` в тексте пройдёт эту цепочку и даст `0x70` (с палитрой
gruvbox, которая стоит по умолчанию, — светлый текст на тёмно-сером).
Тот же текст в синем окне (`BLUE_WINDOW`) получит цвет №6 окна → №13
приложения → `0x1E`.

Правила (как в `TView::mapColor`):

* палитра представления — массив байтов (`&'static [u8]`); байт № n
  (считая с 1) — номер цвета у владельца;
* последнее звено — палитра приложения (`Vec<Attr>`): её элементы — уже
  атрибуты, в том числе 256-цветные;
* **пустая** палитра пропускает номер без изменений (так у групп без своей
  палитры);
* номер 0 или номер за концом палитры дают `ERROR_ATTR` — если элемент
  «горит» красным, значит, у него палитра не от того владельца.

## Палитра приложения

`Program::palette` — `Vec<Attr>` из 135 атрибутов (порядок — как у
`cpAppColor`):

| Номера | Что |
|--------|-----|
| 1 | фон рабочего стола |
| 2–7 | меню и строка состояния: обычный, недоступный, горячая буква, выбранный, выбранный недоступный, выбранная горячая буква |
| 8–15 | синее окно |
| 16–23 | бирюзовое окно |
| 24–31 | серое окно |
| 32–63 | серый диалог |
| 64–95 | синий диалог |
| 96–127 | бирюзовый диалог |
| 128–135 | окно справки |

Готовые палитры (`&[Attr]`):

| Палитра | Что |
|---------|-----|
| `color::palettes::GRUVBOX` | **по умолчанию**: тёмная тема [gruvbox](https://github.com/morhetz/gruvbox) в 256 цветах |
| `APP_COLOR` | классическая цветная палитра Turbo Vision (`cpAppColor`) |
| `APP_BLACK_WHITE`, `APP_MONOCHROME` | чёрно-белая и монохромная (`cpAppBlackWhite`, `cpAppMonochrome`) |

Те же классические палитры байтами, как в C++, — `APP_COLOR_BYTES` и т. д.

`Program::with_terminal` ставит gruvbox, если терминал умеет 256 цветов,
и `APP_COLOR` — если только 16 (в 16 цветах оттенки серого gruvbox
сливаются в один). `Program::new` (тесты, tvision-gui) всегда начинает с
gruvbox. Вернуть классический вид:

```rust
use tvision::*;

fn classic(app: &mut Program) {
    app.palette = color::palettes::APP_COLOR.to_vec();
}
```

Палитру можно менять на ходу — и в 256 цветах:

```rust
use tvision::*;

fn black_and_white(app: &mut Program) {
    app.palette = color::palettes::APP_BLACK_WHITE.to_vec();
}

fn yellow_desktop(app: &mut Program) {
    app.palette[0] = 0x6E; // №1 — фон рабочего стола: жёлтый на коричневом
}

fn teal_desktop(app: &mut Program) {
    app.palette[0] = color::attr256(250, 23); // светло-серый на тёмной морской волне
}
```

### Тема gruvbox

`GRUVBOX` составлена по ролям элементов, а не простой заменой цветов:
фоны — `bg0_h`…`bg4` (рабочий стол темнее окон, диалоги чуть светлее
окон, строки ввода и списки — ещё светлее), основной текст — `fg1`,
горячие буквы — оранжевые, выбранный пункт меню и кнопка в фокусе —
жёлтые, курсор списка — синий, выделение в строке ввода — бирюзовое.
Номера цветов gruvbox в палитре xterm (из `colors/gruvbox.vim`) — в модуле
`color::palettes::gruvbox` (`BG0`, `FG1`, `YELLOW`, `NBLUE`…), ими удобно
поправить отдельные элементы:

```rust
use tvision::*;
use tvision::color::palettes::gruvbox::*;

fn green_menu_selection(app: &mut Program) {
    app.palette[4] = color::attr256(BG0, GREEN); // №5 — выбранный пункт меню
}
```

Тень окон при 256-цветной палитре (фон рабочего стола — цвет xterm) —
`color::SHADOW_ATTR_256`, при классической — `SHADOW_ATTR`.

### Своя тема в 256 цветах

`color::remap` перекрашивает всю палитру: каждый цвет BIOS заменяется
выбранным цветом xterm. Так классический интерфейс получает новую тему
одной строкой (пример `cargo run --example colors`, клавиша F3):

```rust
use tvision::*;

/// Тема «Сумерки»: цвет xterm вместо каждого цвета BIOS 0–15.
const DUSK: [u8; 16] = [235, 24, 71, 30, 131, 96, 137, 252, 242, 74, 114, 116, 210, 176, 222, 255];

fn dusk(app: &mut Program) {
    app.palette = color::remap(color::palettes::APP_COLOR, &DUSK);
}
```

Пользователь меняет её в `ColorDialog` ([глава 10](10-std-dialogs.md#настройка-цветов-colordialog)).

## Палитры окон и диалогов

**Окно** (8 цветов): 1 — рамка неактивного окна, 2 — рамка активного,
3 — значки рамки, 4 — поле полосы прокрутки, 5 — значки полосы,
6 — обычный текст, 7 — выделенный текст, 8 — резерв.
`palettes::BLUE_WINDOW` (по умолчанию у `Window`), `CYAN_WINDOW`,
`GRAY_WINDOW`:

```rust
use tvision::*;

fn gray_window() -> Window {
    let mut w = Window::new(Rect::new(0, 0, 40, 10), "Серое окно", 0);
    w.palette = color::palettes::GRAY_WINDOW;
    w
}
```

**Диалог** (32 цвета): 1–3 — рамка, 4–5 — полоса прокрутки,
6 — статический текст, 7–9 — метка (обычная, подсвеченная, горячая буква),
10–15 — кнопка (обычная, по умолчанию, выбранная, недоступная, горячая
буква, тень), 16–18 — флажки (обычные, выбранный, горячая буква),
19–21 — строка ввода (обычная, выделение, стрелки), 22–23 — значок
истории, 24–25 — полоса окна истории, 26–29 — список (обычный, в фокусе,
выбранный, разделитель), 30 — панель сведений, 31 — недоступный пункт
флажков. `Dialog::set_palette(DialogPalette::Gray | Blue | Cyan)`.

## Свои цвета

1. **Номер из палитры стандартного элемента** — лучший вариант: цвет
   меняется вместе с темой и `ColorDialog`.
2. **Своя палитра**, ссылающаяся на номера владельца:

   ```rust
   use tvision::*;

   struct Badge {
       vs: ViewState,
   }

   /// Цвет 1 — как у текста кнопки по умолчанию, 2 — как у метки в фокусе.
   const BADGE: &[u8] = b"\x0B\x08";

   impl View for Badge {
       tvision::impl_view_basics!();
       fn draw(&self, dc: &mut DrawCtx) {
           dc.fill(self.vs.extent(), ' ', dc.color(1));
           dc.write_str(1, 0, "NEW", dc.color(2));
       }
       fn palette(&self) -> &'static [u8] {
           BADGE // годится только внутри диалога: номера 11 и 8 — диалоговые
       }
   }
   ```

3. **Готовый атрибут** — когда цвет должен быть именно таким (так
   устроен `StaticText::colored`): передавайте атрибут в `DrawBuffer` /
   `DrawCtx` напрямую, без `dc.color`. Такой цвет не меняется темой.

## Цвета таблицы

У таблицы (`Table`) **пустая** палитра: номера цветов сразу уходят
владельцу. Какие номера брать, таблица решает по длине палитры
владельца — `DrawCtx::owner_palette_len()`:

| Владелец | Длина | Текст | Курсор | Заголовок | Сетка |
|----------|-------|-------|--------|-----------|-------|
| окно (`Window`) | 8 | 6 | 7 | 2 | 1 |
| диалог (`Dialog`) | 32 | 26 | 27 | 7 | 29 |
| рабочий стол (палитра приложения) | 135 | 13 | 14 | 9 | 8 |
| иначе | — | `DEFAULT_TABLE_COLORS` | | | |

Так таблица выглядит «своей» и в синем окне, и в сером диалоге, и
меняет цвета вместе с темой. «Зебра» — тот же цвет с чуть другим фоном
(`color::shade_bg`: у фона BIOS переключается бит яркости, у фона xterm
берётся соседний оттенок).

Свои цвета задаются готовыми атрибутами:

```rust
use tvision::*;

fn dark(t: Table) -> Table {
    t.with_colors(TableColors {
        normal: 0x07,
        zebra: 0x87,
        header: 0x0E,
        header_sorted: 0x0A,
        cursor: 0x70,
        cursor_inactive: 0x78,
        selected: 0x1F,
        grid: 0x08,
        row_number: 0x03,
    })
}
```

`owner_palette_len()` пригодится и вашим элементам, которые должны
работать в разных владельцах.

## Вывод в терминал

Цвета BIOS выводятся 16-цветными кодами ANSI (`ESC[30–37m`,
`ESC[90–97m`; `color::bios_to_ansi` меняет местами синий и красный — в
BIOS синий = 1, в ANSI = 4). Терминал показывает их своей цветовой
схемой, поэтому оттенки зависят от его настроек — как и в оригинале.

Цвета xterm выводятся как `ESC[38;5;Nm` (текст) и `ESC[48;5;Nm` (фон) —
если терминал умеет 256 цветов. Режим определяется сам
(`color::detect_color_mode`):

| Условие | Режим |
|---------|-------|
| `TVISION_COLORS=16` или `TVISION_COLORS=256` | как указано (пользователь всегда может выбрать сам) |
| `COLORTERM=truecolor` / `24bit`, `TERM` содержит `256color` или `direct`, Windows Terminal (`WT_SESSION`), iTerm2, Terminal.app, VS Code, WezTerm | 256 цветов |
| `TERM=linux`, `dumb`, `vt100`…, `screen`, `ansi`, `cons25` | 16 цветов |
| иначе (в том числе консоль Windows 10+) | 256 цветов |

В режиме 16 цветов вместо цветов xterm выводятся ближайшие цвета BIOS
(младший байт атрибута) — интерфейс остаётся читаемым.

Программа может выбрать режим сама; со следующей перерисовки экран
выводится заново:

```rust
use tvision::color::{self, ColorMode};

fn force_16_colors() {
    color::set_color_mode(Some(ColorMode::Ansi16)); // None — снова автоматически
    assert_eq!(color::color_mode(), ColorMode::Ansi16);
    color::set_color_mode(None);
}
```

В графическом окне tvision-gui 16 цветов BIOS (и номера xterm 0–15)
берутся из `GuiConfig::palette`, остальные 240 цветов — стандартные
цвета xterm.

## Что изменилось для старого кода

* `Attr` — `u32` вместо `u8`, `AttrPair` — `u64` вместо `u16`. Числа
  вроде `0x1E` работают как раньше. Если атрибут хранился в переменной
  типа `u8`, добавьте `as Attr`: `StaticText::colored(r, text, a as Attr)`.
* Обычный цвет из пары — `color::lo(pair)` вместо `(pair & 0xFF) as u8`.
* палитра по умолчанию — `GRUVBOX`; тесты, сравнивающие цвета на экране
  с числами классической палитры (`0x70`…), либо берут цвет из
  `app.palette[n]`, либо ставят `app.palette = APP_COLOR.to_vec()`;
* `Program::palette` и `ColorDialog::palette` — `Vec<Attr>`;
  `color::palettes::APP_*` — `&[Attr]` (`.to_vec()` работает как раньше).
* Палитры представлений (`fn palette() -> &'static [u8]`) не изменились.
